완료된 Anti-AI·워터마크 삽입 주문의 결과를 내려받을 때 이 엔드포인트를 사용합니다. 한 번의 호출로 결과 파일별 URL과 결과 전체를 받는 URL을 함께 받습니다. 워터마크 주문을 v2·v3 어느 쪽으로 만들었든 응답 형식은 같습니다.

<Warning>
  2026년 10월 8일에 응답 형식이 바뀌었고 `GET /api/v3/orders/{orderId}/files/{fileId}/download`는 삭제되었습니다. [이전 응답과의 차이](#이전-응답과의-차이)를 확인하세요.
</Warning>

## 응답 필드

| 필드 | 타입 | 설명 |
|------|------|------|
| `archiveUrl` | string | 결과 전체를 받는 URL. 항상 있음 |
| `files[]` | array | 결과 파일별 `{ fileId, downloadUrl }` |
| `expiresInSeconds` | integer | URL 유효 시간(초). 최대 3600 |

`files[]`는 [주문 상세 조회](/ko/api-reference/orders/get-order-v3)의 `result.outputFiles[]`와 같은 파일을 같은 순서로 담고 `fileId`도 같습니다. `fileId`로 각 URL을 결과 파일과 그 `inputFileId`에 연결하세요.

### `archiveUrl`이 가리키는 파일

| 주문 | `archiveUrl` |
|------|--------------|
| Anti-AI | 모든 결과 파일의 ZIP |
| v2로 만든 워터마크 삽입 | 모든 결과 파일의 ZIP |
| v3로 만든 워터마크 삽입, 결과 파일 2개 이상 | 모든 결과 파일의 ZIP |
| v3로 만든 워터마크 삽입, 결과 파일 1개 | 그 결과 파일(`files[0].downloadUrl`과 같은 파일) |

`archiveUrl`은 결과 파일 하나이거나 전체 ZIP이므로, 다운로드 버튼 하나에 그대로 연결할 수 있습니다.

### URL 유효 시간

URL은 3600초(1시간) 동안 유효합니다. 주문의 보관 기한(`expiresAt`)이 그보다 먼저 끝나면 남은 시간으로 줄이고, `expiresInSeconds`에 줄인 값을 넣습니다. URL을 저장해 두지 말고 내려받을 때마다 이 엔드포인트를 다시 호출하세요.

## 결과 파일 모두 내려받기

<CodeGroup>
```javascript Node.js
import { writeFile } from 'node:fs/promises';

const headers = { Authorization: 'Bearer YOUR_API_KEY' };
const base = `https://api.bizmori.com/api/v3/orders/${orderId}`;

const { data: order } = await (await fetch(base, { headers })).json();
const { data: download } = await (await fetch(`${base}/download`, { headers })).json();

// files[]와 result.outputFiles[]는 fileId 값과 순서가 같습니다.
const names = new Map(order.result.outputFiles.map((file) => [file.fileId, file.fileName]));
for (const { fileId, downloadUrl } of download.files) {
  const res = await fetch(downloadUrl);
  await writeFile(`${fileId}-${names.get(fileId)}`, Buffer.from(await res.arrayBuffer()));
}
```

```python Python
import requests

headers = {'Authorization': 'Bearer YOUR_API_KEY'}
base = f'https://api.bizmori.com/api/v3/orders/{order_id}'

order = requests.get(base, headers=headers).json()['data']
download = requests.get(f'{base}/download', headers=headers).json()['data']

# files[]와 result.outputFiles[]는 fileId 값과 순서가 같습니다.
names = {f['fileId']: f['fileName'] for f in order['result']['outputFiles']}
for item in download['files']:
    res = requests.get(item['downloadUrl'])
    with open(f"{item['fileId']}-{names[item['fileId']]}", 'wb') as out:
        out.write(res.content)
```
</CodeGroup>

## 오류

아래 순서로 오류를 검사하고 처음 해당하는 오류를 반환합니다.

| 순서 | 조건 | HTTP | `code` |
|------|------|------|--------|
| 1 | 주문이 없거나 다른 계정의 주문 | 404 | `ORDER_NOT_FOUND` |
| 2 | 워터마크 검출·AI Detection 주문(보관 기한이 지났어도 동일) | 400 | `ORDER_TYPE_CANT_DOWNLOAD` |
| 3 | 보관 기한 만료 | 400 | `ORDER_EXPIRED` |
| 3 | 보관 기한을 확인할 수 없음 | 409 | `FILE_RETENTION_UNKNOWN` |
| 4 | `status`가 `pending`, `inProgress`, `failed` | 400 | `ORDER_NOT_COMPLETED` |

`orderId` 형식이 잘못되면 `400 VALIDATION_FAILED`를 반환합니다.

## 이전 응답과의 차이

2026년 10월 8일부터 이 엔드포인트는 위 형식으로 응답합니다. 하위 호환되지 않는 변경입니다.

| 이전 동작 | 현재 |
|-----------|------|
| 응답 `{ downloadUrl, expiresInSeconds }` | `{ archiveUrl, files, expiresInSeconds }`. `downloadUrl` 대신 `archiveUrl` |
| v3 워터마크 삽입 주문만 지원 | Anti-AI 주문, v2·v3로 만든 워터마크 삽입 주문 지원 |
| URL 300초 유효 | 최대 3600초. 보관 기한까지로 제한 |
| 미완료 주문: `400 VALIDATION_FAILED` | `400 ORDER_NOT_COMPLETED` |
| 워터마크 검출·AI Detection 주문: 지원 안 함 | 계속 지원하지 않으며 전용 오류 `400 ORDER_TYPE_CANT_DOWNLOAD` 반환 |
| 결과 파일 하나를 받는 `GET /api/v3/orders/{orderId}/files/{fileId}/download` | 삭제됨. 이 엔드포인트의 `files[]` 사용 |

deprecated된 [`GET /api/v2/orders/{orderId}/download`](/ko/api-reference/orders/download-order)는 기존 응답을 그대로 반환합니다.
