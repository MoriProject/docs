주문 상태를 확인하고 결과를 읽을 때 이 엔드포인트를 사용합니다. Anti-AI, AI Detection, 워터마크 삽입, 워터마크 검출 등 모든 주문 종류를 v2·v3 어느 쪽으로 만들었든 조회할 수 있습니다. 최상위 필드는 모든 주문이 같고, `type`에 따라 `result`만 달라집니다.

<Warning>
  2026년 10월 8일에 응답 형식이 바뀌었습니다. 이 엔드포인트에서 `files`, `outputs`, 최상위 `reports`, `fileCount`, `statusCode`를 읽고 있다면 [이전 응답과의 차이](#이전-응답과의-차이)를 확인하세요.
</Warning>

## 공통 필드

| 필드 | 타입 | 설명 |
|------|------|------|
| `type` | string | `antiAi`, `aiDetection`, `watermarkEmbed`, `watermarkExtract` 중 하나 |
| `orderId` | string | 주문 ID |
| `orderName` | string \| null | 주문 이름 |
| `channel` | string | `api` 또는 `web` |
| `status` | string | [상태](#상태)의 5가지 값 중 하나 |
| `createdAt`, `updatedAt` | string | ISO 8601 일시 |
| `expiresAt` | string \| null | 주문 파일을 받을 수 있는 기한. 주문이 처음 완료될 때 완료 시각 + `retentionDays`로 정해지며 그 전에는 임시값입니다. [보관 기간과 URL 유효 시간](#보관-기간과-url-유효-시간) 참고 |
| `retentionDays` | integer \| null | 파일 보관 기간(일, 7 또는 30). 주문을 만들 때 계정의 파일 보관 설정에서 가져와 주문에 고정 |
| `thumbnailImageUrl` | string \| null | 썸네일 이미지 URL |
| `processingDelayed` | boolean | v3로 만든 워터마크 주문이 수동 복구를 기다리면 `true`. 그 외 주문은 항상 `false` |
| `errors` | object \| string \| null | 실패 정보. 실패하지 않은 주문은 `null`. [실패 정보](#실패-정보) 참고 |
| `inputFiles` | array | 입력 파일. [입력 파일](#입력-파일) 참고 |
| `result` | object \| null | 주문 종류별 결과. [주문 종류별 결과](#주문-종류별-결과) 참고 |

## 상태

| `status` | 의미 | `result` |
|----------|------|----------|
| `pending` | 파일 업로드 대기. `inputFiles[].uploadUrl`이 있음 | `null` |
| `inProgress` | 처리 중 | `null` |
| `complete` | 완료 | 객체 |
| `failed` | 처리 실패. 사유는 `errors`에 있음 | `null` |
| `expired` | 주문에 고정된 보관 기간이 끝나 파일을 더 이상 받을 수 없음. URL을 발급하지 않음 | `null` |

v2로 만든 워터마크 검출 주문 중 저장 status가 `detected` 또는 `undetected`인 주문은 `complete`로 반환합니다. 판정 결과는 `result.detectionStatus`에서 읽으세요.

## 입력 파일

`inputFiles[]`의 각 항목에는 `fileId`와 `fileName`이 있으며 주문 생성 요청의 순서를 따릅니다. 아래 두 키는 해당할 때만 나옵니다. 해당하지 않으면 `null`이 아니라 키 자체가 없습니다.

- `role`은 `watermarkExtract` 주문에만 나옵니다. `original`은 워터마크를 넣은 원본 파일, `query`는 검사할 파일입니다.
- `uploadUrl`은 `status`가 `pending`이고 해당 파일이 아직 업로드 대기 중일 때만 나옵니다. 이 URL로 파일을 PUT하세요. 업로드 URL이 만료되면 이 엔드포인트를 다시 호출해 새 URL을 받으세요.

이 응답과 [다운로드 응답](/ko/api-reference/orders/download-order-v3)의 모든 `fileId`는 `"11"`처럼 숫자로만 된 문자열입니다. `-` 같은 구분자는 들어가지 않습니다.

## 실패 정보

`errors`는 주문 처리 실패 정보입니다. API 오류 응답 본문 `{ code }`와는 다른 값입니다.

- 실패하지 않은 주문은 `null`입니다. 실패한 뒤 보관 기한이 지나 `expired`가 된 주문은 실패 때 저장한 값을 그대로 유지합니다.
- v3로 만든 워터마크 주문은 저장된 값을 `{ errorCode, errorMessage }`로 바꿉니다. 저장값이 `null`이면 실패 주문이어도 `errors`는 `null`입니다.
- 그 밖의 주문(Anti-AI, AI Detection, v2로 만든 워터마크 주문)은 저장값을 그대로 반환합니다. 보통 객체이며 `errorCode` 없이 `errorMessage`만 있을 수 있고, 일부 오래된 주문은 문자열을 반환합니다.

`null`, 객체, 문자열을 모두 처리하세요.

## 보관 기간과 URL 유효 시간

- `retentionDays`(7 또는 30)는 주문을 만들 때 계정의 파일 보관 설정에서 가져와 주문에 고정합니다. 나중에 설정을 바꿔도 기존 주문은 바뀌지 않습니다.
- `expiresAt`은 주문이 처음 완료될 때 완료 시각 + `retentionDays`로 정해집니다. `pending`·`inProgress`일 때는 임시값입니다. 결과 파일은 `expiresAt`까지 받을 수 있습니다.
- `retentionDays`와 `expiresAt`은 데이터 예외에서만 `null`입니다. `expiresAt`이 `null`이어도 무기한 보관이 아닙니다. Anti-AI·워터마크 삽입 주문의 [다운로드](/ko/api-reference/orders/download-order-v3)는 `409 FILE_RETENTION_UNKNOWN`을 반환하고, 워터마크 검출·AI Detection 주문은 다운로드가 주문 종류를 보관 기한보다 먼저 검사하므로 `400 ORDER_TYPE_CANT_DOWNLOAD`를 반환합니다.
- 이미지 URL은 보관 기간과 별개로 유효 시간이 있습니다. Anti-AI·AI Detection·v2 워터마크 주문의 저장된 이미지는 최대 7일이며 `expiresAt`까지만 서명합니다. v3로 만든 워터마크 주문의 썸네일은 보관 기한 전에만 발급하지만 15분으로 고정 서명하므로, 발급된 URL이 `expiresAt` 뒤까지 유효할 수 있습니다. 상태별 고정 이미지는 서명 URL이 아닙니다. 새 URL이 필요하면 주문을 다시 조회하세요.

- **Pending**: 아직 업로드 대기 중인 파일에만 `uploadUrl`이 있습니다. 워터마크 삽입, Anti-AI, AI Detection 주문에는 `role`이 없습니다.
- **Failed**: `errors`에 사유가 있고 `result`는 `null`입니다. `errorMessage`는 오류 코드별 고정 한국어 안내 문구입니다.
- **Expired**: 보관 기한이 지난 주문도 조회할 수 있지만 `result`는 `null`이고 URL을 발급하지 않습니다. Anti-AI·워터마크 삽입 주문의 [다운로드](/ko/api-reference/orders/download-order-v3)는 `400 ORDER_EXPIRED`를 반환합니다.

## 이전 응답과의 차이

2026년 10월 8일부터 이 엔드포인트는 위 형식으로 응답합니다. 하위 호환되지 않는 변경입니다.

| 이전 응답 | 현재 |
|-----------|------|
| `files[]` (v3 워터마크 주문) | `inputFiles[]`. `uploadUrl`은 `pending` 주문에만 있음 |
| `outputs[]` (v3 워터마크 주문) | `result.outputFiles[]`. `outputIndex`, `status`, `mediaKind`는 더 이상 반환하지 않음 |
| `"601-1"` 형식의 결과 `fileId` | `"201"` 같은 숫자 문자열 |
| 최상위 `reports[]` | `result.reports[]` |
| `detectionStatus: "not_detected"` | `"undetected"` |
| `fileCount` | `inputFiles.length` |
| `statusCode` (AI Detection) | `result.verdict` |
| `statusCode`와 `status: "detected"` / `"undetected"` (v2 워터마크 검출) | `status: "complete"`와 `result.detectionStatus` |
| `watermarks[]` (v2 워터마크 삽입) | `result.outputFiles[].watermarkText` |
| 최상위 `watermarkText`, `probability`, `options`, `originalImageUrl`, `heatmapUrl`, `overlayUrl` | `result` 안으로 이동 |

deprecated된 [`GET /api/v2/orders/{orderId}`](/ko/api-reference/orders/get-order)는 기존 응답을 그대로 반환합니다.

## 테스트 키

`sk_test_` 키로 호출하면 키가 속한 계정이 소유한 테스트 주문만 위 형식으로 반환합니다. 이 조회는 읽기 전용이 아니며, `inProgress` 테스트 주문을 `complete`·`failed`로 바꾸고 테스트 웹훅 이벤트를 보낼 수 있습니다. 테스트 주문의 상태 변화는 [테스트 API 키](/ko/test-api-keys)를 참고하세요.
