## 이미지 업로드 방법

응답에서 받은 `uploadUrl`을 사용하여 `PUT` 요청으로 이미지를 업로드합니다. 일반 키는 프리사인드 저장소 URL을 반환하고, 테스트 키는 요청 본문을 소비한 뒤 폐기하는 ContentCare 테스트 업로드 URL을 반환합니다:

```bash
curl -X PUT "UPLOAD_URL" \
  -H "Content-Type: image/jpeg" \
  --data-binary @photo.jpg
```

<Note>
  일반 프리사인드 업로드 URL과 테스트 업로드 URL은 모두 **1시간** 후 만료되며 URL 자체에 인증 정보가 있으므로 Bearer 헤더를 붙이지 않습니다. 일반 키의 `fileKey`는 S3 object key이고, 테스트 키의 `fileKey`는 격리된 logical key입니다. 영속 테스트 주문이 꺼진 환경에서는 테스트 키가 저장되지 않는 목업 응답을 받으며, 이때 `test.invalid` 주소의 `uploadUrl`로는 업로드할 수 없습니다. URL이 만료되기 전에 업로드하고 [주문 확인](/ko/api-reference/ai-detection/confirm-order) 엔드포인트를 호출하세요.
</Note>

## 감지 결과 확인

업로드를 확인하면 주문 상태가 `inProgress`로 변경됩니다. 감지가 완료되면 다음 방법으로 결과를 확인할 수 있습니다:

1. **웹훅** — `order.aiDetection.completed` 또는 `order.aiDetection.failed` 이벤트 구독
2. **폴링** — [주문 상세 조회](/ko/api-reference/orders/get-order-v3)를 `status`가 `complete` 또는 `failed`가 될 때까지 호출

주문이 `complete`가 되면 감지 결과는 `result`에 들어 있습니다. 아래 예시는 주문 공통 필드를 생략했습니다. 전체 응답은 [주문 상세 조회](/ko/api-reference/orders/get-order-v3)를 참고하세요.

```json
{
  "data": {
    "type": "aiDetection",
    "orderId": "...",
    "status": "complete",
    "result": {
      "verdict": "likely_ai",
      "probability": 0.97,
      "options": {
        "generateHeatmap": true,
        "generateOverlay": false,
        "generateThumbnail": true
      },
      "originalImageUrl": "https://...",
      "heatmapUrl": "https://...",
      "overlayUrl": null
    }
  }
}
```

<Info>
  테스트 주문은 파일명으로 감지 결과를 고정합니다. `_ai`는 확률 `0.98`, `_human`은 확률 `0.02`를 반환합니다. 테스트 주문은 다운로드 가능한 히트맵·오버레이 파일을 만들지 않습니다.
</Info>

### 판정

| `result.verdict` | 의미 |
|---|---|
| `likely_ai` | AI 생성일 가능성이 높음 |
| `uncertain_ai` | AI 생성일 가능성이 있음 |
| `uncertain_real` | AI 생성이 아닐 가능성이 있음 |
| `likely_real` | AI 생성이 아닐 가능성이 높음 |

판정은 서버가 `result.probability`로 정합니다. 판정 값은 AI 생성일 가능성의 정도를 나타내며 AI 생성 여부를 확정하지 않습니다.
