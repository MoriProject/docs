이 가이드는 v3 API로 비가시성 워터마크를 삽입하는 과정을 주문 생성부터 워터마크가 삽입된 파일 다운로드까지 안내합니다.

이 API의 모든 엔드포인트는 순수 HTTPS와 JSON으로 동작하므로, 서버에서든 브라우저에서든 똑같이 호출할 수 있습니다. 각 단계에는 **React** 탭이 있고, 그대로 복사해 쓸 수 있는 [전체 컴포넌트](#전체-react-예제)는 페이지 하단에 있습니다.

<Warning>
  v2 워터마크 삽입 엔드포인트(`POST /api/v2/orders/wtr-embed`)는 2026년 10월 9일 09:00 KST(00:00 UTC)에 지원 종료 예정입니다. 이 가이드는 v3 API를 기준으로 설명합니다. 이미 v2를 사용하고 있다면 [v2에서 v3로 마이그레이션](#v2에서-v3로-마이그레이션)을 참고하세요.
</Warning>

## 사전 준비

- BIZ MORI API 키 ([여기서 발급](https://app.bizmori.com/keys))
- 워터마크를 삽입할 이미지 또는 PDF 파일 (`jpg`, `jpeg`, `png`, `webp`, `bmp`, `tif`, `tiff`, `pdf`)

<Info>
  자동 발급된 [`sk_test_` 키](/ko/test-api-keys)를 사용하면 실제 워터마크 처리나 크레딧 사용 없이 v3 흐름 전체를 검증할 수 있습니다. 테스트 주문은 업로드 후 약 5초 뒤에 완료되며, 다운로드 URL은 실제 결과 대신 고정된 샘플 파일을 반환합니다. 실제로 워터마크가 삽입된 파일이 필요하면 일반 API 키를 사용하세요.
</Info>

## 동작 방식

1. 파일 이름과 파일별 워터마크 문구로 **주문을 생성**합니다.
2. 응답의 프리사인드 `uploadUrl`로 **각 파일을 `PUT` 업로드**합니다. 모든 파일이 업로드되면 처리가 자동으로 시작되며, confirm 단계는 없습니다.
3. `GET /api/v3/orders/{orderId}`를 폴링하거나 [웹훅](/ko/webhooks)을 받아 **주문 완료를 기다립니다**.
4. **결과를 다운로드**합니다. 한 번의 호출로 결과 파일별 URL과 결과 전체 URL을 함께 받습니다.

## 1단계: 주문 생성

워터마크 삽입 주문을 생성합니다. 파일마다 워터마크 문구를 1~10개 지정할 수 있으며, **문구 하나마다 결과 파일이 하나씩 만들어지고 1크레딧이 사용됩니다**. 아래 요청은 이미지 하나에 문구 두 개를 삽입하므로 결과 파일 2개가 만들어지고 2크레딧이 사용됩니다.

  주문 하나에 파일을 최대 100개까지 넣을 수 있고, 이미지와 PDF를 섞어도 됩니다. 이미 공개된 파일이라면 업로드하는 대신 `originalFileUrl`에 HTTPS URL을 지정하세요. BIZ MORI가 파일을 직접 내려받으며(최대 32 MiB, 리다이렉트는 따라가지 않음), 이 파일의 `uploadUrl`은 `null`입니다.
</Tip>

<Note>
  같은 `idempotencyKey`는 같은 요청을 재시도할 때만 다시 사용하세요. 이 경우 새 주문을 만들지 않고 기존 주문을 반환합니다. 같은 키로 요청 본문이 다른 요청을 보내면 `409 WATERMARK_V2_CONFLICT`를 반환합니다.
</Note>

## 2단계: 파일 업로드

각 파일을 프리사인드 `uploadUrl`로 PUT 업로드합니다. 스토리지로 직접 올리는 업로드이므로 **Authorization 헤더는 필요 없습니다**.

`Content-Type` 헤더는 파일 확장자에 맞는 값으로 보내야 합니다. 프리사인드 URL이 이 타입으로 서명되어 있어 다른 값을 보내면 업로드가 거부됩니다.

| 확장자 | `Content-Type` |
|--------|----------------|
| `jpg`, `jpeg` | `image/jpeg` |
| `png` | `image/png` |
| `webp` | `image/webp` |
| `bmp` | `image/bmp` |
| `tif`, `tiff` | `image/tiff` |
| `pdf` | `application/pdf` |

<CodeGroup>
```bash cURL
curl -X PUT "https://s3.ap-northeast-2.amazonaws.com/..." \
  -H "Content-Type: image/jpeg" \
  --data-binary @photo.jpg
```

```javascript Node.js
import { readFile } from 'node:fs/promises';

const upload = await fetch(order.files[0].uploadUrl, {
  method: 'PUT',
  headers: { 'Content-Type': 'image/jpeg' },
  body: await readFile('photo.jpg'),
});
if (!upload.ok) throw new Error(`UPLOAD_FAILED_${upload.status}`);
```

```jsx React
// 프리사인드 URL은 파일 확장자에 맞는 타입으로 서명되어 있으므로,
// `file.type` 대신 파일 이름에서 Content-Type을 정합니다.
const CONTENT_TYPES = {
  jpg: 'image/jpeg', jpeg: 'image/jpeg', png: 'image/png', webp: 'image/webp',
  bmp: 'image/bmp', tif: 'image/tiff', tiff: 'image/tiff', pdf: 'application/pdf',
};
const contentTypeOf = (name) => CONTENT_TYPES[name.split('.').pop().toLowerCase()];

// fetch()는 업로드 진행률을 알려줄 수 없으므로, PUT에는 XMLHttpRequest를 사용합니다.
function putFile(file, uploadUrl, onProgress) {
  return new Promise((resolve, reject) => {
    const xhr = new XMLHttpRequest();
    xhr.open('PUT', uploadUrl);
    xhr.setRequestHeader('Content-Type', contentTypeOf(file.name));

    xhr.upload.onprogress = (event) => {
      if (event.lengthComputable) onProgress(event.loaded / event.total);
    };
    xhr.onload = () =>
      xhr.status < 300 ? resolve() : reject(new Error(`UPLOAD_FAILED_${xhr.status}`));
    xhr.onerror = () => reject(new Error('UPLOAD_NETWORK_ERROR'));

    xhr.send(file);
  });
}

await putFile(file, order.files[0].uploadUrl, (ratio) => setProgress(ratio));
```

```python Python

```

</Note>

## 3단계: 주문 완료 대기

`status`가 `complete`가 될 때까지 주문을 폴링하세요. 폴링 대신 [웹훅](/ko/webhooks)을 설정하면 `order.watermarkEmbed.completed` 또는 `order.watermarkEmbed.failed` 이벤트를 받을 수 있습니다.

<CodeGroup>
```bash cURL
curl https://api.bizmori.com/api/v3/orders/1234567890 \
  -H "Authorization: Bearer YOUR_API_KEY"
```

```javascript Node.js
const sleep = (ms) => new Promise((resolve) => setTimeout(resolve, ms));

async function waitForOrder(orderId) {
  for (let delay = 2000; ; delay = Math.min(delay * 1.5, 15000)) {
    const res = await fetch(`${API_BASE}/orders/${orderId}`, { headers });
    const { data } = await res.json();
    if (['complete', 'failed', 'expired'].includes(data.status)) return data;
    await sleep(delay);
  }
}

const finished = await waitForOrder(order.orderId);
// finished.result.outputFiles에는 워터마크 문구마다 항목이 하나씩 있습니다
```

```jsx React
const sleep = (ms) => new Promise((resolve) => setTimeout(resolve, ms));

// 대기 시간이 길어질수록 폴링 간격도 늘립니다: 빠른 응답은 빠르게 유지하고,
// 오래 걸리는 작업이 API를 계속 두드리지 않도록 합니다. 무한정 폴링하지 않고 10분 후 포기합니다.
async function pollOrder(orderId, { onStatus, timeoutMs = 10 * 60 * 1000 } = {}) {
  const deadline = Date.now() + timeoutMs;
  let delay = 2000;

  while (Date.now() < deadline) {
    const order = await api(`/orders/${orderId}`);
    onStatus?.(order.status);
    if (['complete', 'failed', 'expired'].includes(order.status)) return order;

    await sleep(delay);
    delay = Math.min(delay * 1.5, 15000);
  }
  throw new Error('ORDER_POLL_TIMEOUT');
}
```

```python Python
import time

def wait_for_order(order_id):
    delay = 2
    while True:
        res = requests.get(f'{API_BASE}/orders/{order_id}', headers=HEADERS)
        data = res.json()['data']
```

</CodeGroup>

| `status` | 의미 |
|----------|------|
| `pending` | 파일 업로드 대기 중 |
| `inProgress` | 처리 중 |
| `complete` | 다운로드 가능 |
| `failed` | 처리 실패. 사용한 크레딧은 복구됩니다 |
| `expired` | 보관 기간이 끝나 파일이 삭제됨 |

주문이 `complete`가 되면 `result.outputFiles[]`에 워터마크 문구마다 결과 파일이 하나씩 나옵니다. 주문 상세는 모든 주문 종류에서 같은 형식이며, 전체 필드는 [주문 상세 조회](/ko/api-reference/orders/get-order-v3)를 참고하세요.

```json
{
  "data": {
    "type": "watermarkEmbed",
    "orderId": "1234567890",
    "orderName": "photo.jpg",
    "channel": "api",
    "status": "complete",
    "createdAt": "2026-10-03T03:00:00.000Z",
    "updatedAt": "2026-10-03T03:00:40.000Z",
    "expiresAt": "2026-10-10T03:00:00.000Z",
    "retentionDays": 7,
    "thumbnailImageUrl": "https://...",
    "processingDelayed": false,
    "errors": null,
    "inputFiles": [
      { "fileId": "501", "fileName": "photo.jpg" }
    ],
    "result": {
      "outputFiles": [
        { "fileId": "8812", "fileName": "photo.jpg", "inputFileId": "501", "watermarkText": "PARTNER-A" },
        { "fileId": "8813", "fileName": "photo.jpg", "inputFileId": "501", "watermarkText": "PARTNER-B" }
      ]
    }
  }
}
```

`processingDelayed`가 `true`이면 자동 재시도가 모두 소진되어 수동 복구를 기다리는 중입니다. 주문은 `inProgress` 상태로 유지되므로 계속 폴링하거나 웹훅을 기다리세요.

`order.watermarkEmbed.failed` 웹훅에는 실패 원인을 알려주는 `errorCode`가 포함됩니다. 이벤트 페이로드와 에러 코드는 [웹훅](/ko/webhooks)을 참고하세요.

## 4단계: 결과 다운로드

`status`가 `complete`가 되면 다운로드 URL을 요청합니다. 한 번의 호출로 결과 파일별 URL(`files[]`)과 결과 전체를 받는 URL(`archiveUrl`)을 함께 받습니다. 결과 파일이 하나면 `archiveUrl`은 그 파일을, 여러 개면 ZIP 파일을 가리킵니다.

<CodeGroup>
```bash cURL
curl https://api.bizmori.com/api/v3/orders/1234567890/download \
  -H "Authorization: Bearer YOUR_API_KEY"
```

```javascript Node.js
const res = await fetch(`${API_BASE}/orders/${order.orderId}/download`, { headers });
const { data } = await res.json();
// data.archiveUrl과 data.files[].downloadUrl은 data.expiresInSeconds초(최대 3600초) 동안 유효합니다
```

```jsx React

window.location.assign(archiveUrl);
```

```python Python

archive_url = res.json()['data']['archiveUrl']
```
</CodeGroup>

**응답:**
```json
{
  "data": {
    "archiveUrl": "https://s3.ap-northeast-2.amazonaws.com/...",
    "files": [
      { "fileId": "8812", "downloadUrl": "https://s3.ap-northeast-2.amazonaws.com/..." },
      { "fileId": "8813", "downloadUrl": "https://s3.ap-northeast-2.amazonaws.com/..." }
    ],
    "expiresInSeconds": 3600
  }
}
```

- `files[]`는 `result.outputFiles[]`와 같은 결과 파일을 같은 순서로 담고 `fileId`도 같습니다. `fileId`로 맞춰 보면 각 파일에 어떤 워터마크 문구가 들어갔는지 알 수 있습니다.
- URL은 최대 **3600초** 동안 유효하며, 보관 기한이 먼저 끝나면 그보다 짧습니다. 저장해 두지 말고 다운로드할 때마다 새로 요청하세요. `expiresAt`이 지나면 이 엔드포인트는 `400 ORDER_EXPIRED`를 반환합니다.

<Note>
  테스트 주문에서는 `archiveUrl`과 `files[]`가 고정된 샘플 파일을 가리킵니다(결과가 여러 개면 ZIP). 실제로 워터마크가 삽입된 파일이 아닙니다.
</Note>

## 전체 React 예제

위 내용을 모두 하나의 컴포넌트로 연결했습니다: 진행률을 보여주는 단일 파일 업로드, 추가/삭제와 중복 검사가 가능한 워터마크 문구 목록, 백오프 폴링, 누를 때마다 새 URL을 받는 다운로드 버튼까지. React 외에 별도의 의존성은 없습니다.

```jsx WatermarkEmbedUploader.jsx
import { useMemo, useRef, useState } from 'react';

const API_BASE = 'https://api.bizmori.com/api/v3';
const API_KEY = import.meta.env.VITE_MORI_API_KEY;

const CONTENT_TYPES = {
  jpg: 'image/jpeg', jpeg: 'image/jpeg', png: 'image/png', webp: 'image/webp',
  bmp: 'image/bmp', tif: 'image/tiff', tiff: 'image/tiff', pdf: 'application/pdf',
};
const ACCEPT_FORMATS = Object.keys(CONTENT_TYPES).map((ext) => `.${ext}`).join(',');
const MAX_WATERMARKS = 10;
const MAX_TEXT_LENGTH = 1000;

const sleep = (ms) => new Promise((resolve) => setTimeout(resolve, ms));
const contentTypeOf = (name) => CONTENT_TYPES[name.split('.').pop().toLowerCase()];

async function api(path, { method = 'GET', body, idempotencyKey } = {}) {
  // 재시도는 호출자의 idempotency key를 그대로 재사용하므로, 재시도된 생성 요청이
  // 두 번째 주문을 만들어내는 일은 없습니다. 인증 실패는 `AUTH_*` 코드로 나타나며,
  // 재시도해도 소용없으므로 아래 throw로 넘어갑니다.
  for (let attempt = 0; ; attempt++) {
    const res = await fetch(`${API_BASE}${path}`, {
      method,
      headers: {
        Authorization: `Bearer ${API_KEY}`,
        ...(body && { 'Content-Type': 'application/json' }),
      },
      body: body && JSON.stringify({ idempotencyKey, ...body }),
    });

    if (!res.ok) {
      const { code } = await res.json().catch(() => ({}));
      // 429는 두 경우를 포함합니다: 일시적인 레이트 리밋, 그리고 요금제 사용량이 소진되어
      // 재시도해도 풀리지 않는 PLAN_LIMIT_EXCEEDED.
      if (res.status === 429 && code !== 'PLAN_LIMIT_EXCEEDED' && attempt < 3) {
        await sleep(2 ** attempt * 1000);
        continue;
      }
      throw new Error(code ?? `HTTP_${res.status}`);
    }
    return (await res.json()).data;
  }
}

function putFile(file, uploadUrl, onProgress) {
  return new Promise((resolve, reject) => {
    const xhr = new XMLHttpRequest();
    xhr.open('PUT', uploadUrl);
    xhr.setRequestHeader('Content-Type', contentTypeOf(file.name));

    xhr.upload.onprogress = (event) => {
      if (event.lengthComputable) onProgress(event.loaded / event.total);
    };
    xhr.onload = () =>
      xhr.status < 300 ? resolve() : reject(new Error(`UPLOAD_FAILED_${xhr.status}`));
    xhr.onerror = () => reject(new Error('UPLOAD_NETWORK_ERROR'));

    xhr.send(file);
  });
}

async function pollOrder(orderId, { onStatus, timeoutMs = 10 * 60 * 1000 } = {}) {
  const deadline = Date.now() + timeoutMs;
  let delay = 2000;

  while (Date.now() < deadline) {
    const order = await api(`/orders/${orderId}`);
    onStatus?.(order.status);
    if (['complete', 'failed', 'expired'].includes(order.status)) return order;

    await sleep(delay);
    delay = Math.min(delay * 1.5, 15000);
  }
  throw new Error('ORDER_POLL_TIMEOUT');
}

export default function WatermarkEmbedUploader() {
  const [file, setFile] = useState(null);
  // 지연 초기화: 이렇게 하지 않으면 렌더링할 때마다 crypto.randomUUID()가 실행됩니다.
  const [watermarks, setWatermarks] = useState(() => [{ id: crypto.randomUUID(), text: '' }]);
  const [progress, setProgress] = useState(0);
  const [status, setStatus] = useState('idle');
  const [error, setError] = useState(null);
  const [orderId, setOrderId] = useState(null);
  const inFlight = useRef(false);

  const busy = status !== 'idle' && status !== 'complete';

  // 처음 나온 문구 이후의 같은 문구를 모두 중복으로 표시합니다. 빈 행은
  // 아래의 "빈 문구 금지" 규칙에서 이미 걸러지므로 제외합니다.
  const duplicateIds = useMemo(() => {
    const seen = new Map();
    const duplicates = new Set();
    watermarks.forEach((watermark) => {
      const text = watermark.text.trim();
      if (text === '') return;
      if (seen.has(text)) duplicates.add(watermark.id);
      else seen.set(text, watermark.id);
    });
    return duplicates;
  }, [watermarks]);

  const canSubmit =
    file !== null &&
    contentTypeOf(file.name) !== undefined &&
    watermarks.length > 0 &&
    watermarks.every((watermark) => watermark.text.trim() !== '') &&
    duplicateIds.size === 0 &&
    !busy;

  function updateWatermark(id, text) {
    setWatermarks((prev) => prev.map((watermark) => (watermark.id === id ? { ...watermark, text } : watermark)));
  }

  function addWatermark() {
    setWatermarks((prev) => [...prev, { id: crypto.randomUUID(), text: '' }]);
  }

  function removeWatermark(id) {
    setWatermarks((prev) => prev.filter((watermark) => watermark.id !== id));
  }

  async function embedWatermarks(event) {
    event.preventDefault();
    if (inFlight.current || !canSubmit) return;
    inFlight.current = true;

    // 선택 값을 고정해 둡니다. 요청이 진행되는 동안 사용자가 폼을 수정할 수 있지만,
    // 업로드에는 제출 시점의 값을 사용해야 합니다.
    const selectedFile = file;
    const selectedWatermarks = watermarks;
    setError(null);
    setOrderId(null);
    setProgress(0);

    try {
      setStatus('creating order');
      const order = await api('/orders/wtr-embed', {
        method: 'POST',
        idempotencyKey: crypto.randomUUID(),
        body: {
          files: [
            {
              fileName: selectedFile.name,
              watermarks: selectedWatermarks.map((watermark) => ({ text: watermark.text.trim() })),
            },
          ],
        },
      });

      setOrderId(order.orderId);
      setStatus('uploading');
      await putFile(selectedFile, order.files[0].uploadUrl, setProgress);

      // confirm 단계 없음 — 업로드가 끝나면 처리가 자동으로 시작됩니다.
      const finished = await pollOrder(order.orderId, { onStatus: setStatus });
      if (finished.status !== 'complete') throw new Error(`ORDER_${finished.status.toUpperCase()}`);

      setStatus('complete');
    } catch (caught) {
      setError(caught.message);
      setStatus('idle');
    } finally {
      inFlight.current = false;
    }
  }

  // 다운로드 URL은 1시간 안에 만료되므로 누를 때마다 새로 받습니다.
  async function download() {
    try {
      const { archiveUrl } = await api(`/orders/${orderId}/download`);
      window.location.assign(archiveUrl);
    } catch (caught) {
      setError(caught.message);
    }
  }

  return (
    <form onSubmit={embedWatermarks}>
      <input
        type="file"
        accept={ACCEPT_FORMATS}
        disabled={busy}
        onChange={(event) => {
          setFile(event.target.files[0] ?? null);
          setError(null);
          setProgress(0);
          setStatus('idle');
        }}
      />

      <ul>
        {watermarks.map((watermark, index) => (
          <li key={watermark.id}>
            <input
              type="text"
              value={watermark.text}
              maxLength={MAX_TEXT_LENGTH}
              disabled={busy}
              placeholder={`Watermark text #${index + 1}`}
              onChange={(event) => updateWatermark(watermark.id, event.target.value)}
              style={{ borderColor: duplicateIds.has(watermark.id) ? 'red' : undefined }}
            />
            <button type="button" disabled={busy || watermarks.length === 1} onClick={() => removeWatermark(watermark.id)}>
              Remove
            </button>
          </li>
        ))}
      </ul>
      <button type="button" disabled={busy || watermarks.length >= MAX_WATERMARKS} onClick={addWatermark}>
        Add watermark text ({watermarks.length}/{MAX_WATERMARKS})
      </button>

      <p>This order uses {watermarks.length} credit{watermarks.length === 1 ? '' : 's'}.</p>
      <button type="submit" disabled={!canSubmit}>
        Embed watermark{watermarks.length === 1 ? '' : 's'}
      </button>

      {status !== 'idle' && <p>Status: {status}</p>}
      {status === 'uploading' && <p>Upload progress: {Math.round(progress * 100)}%</p>}

      {status === 'complete' && (
        <button type="button" onClick={download}>
          Download {watermarks.length === 1 ? 'watermarked file' : 'ZIP'}
        </button>
      )}
      {error && <p role="alert">Failed: {error}{orderId && ` (orderId: ${orderId})`}</p>}
    </form>
  );
}
```

<Note>
  `import.meta.env.VITE_MORI_API_KEY`는 Vite 문법입니다. Next.js에서는 `process.env.NEXT_PUBLIC_MORI_API_KEY`를, 그 밖의 번들러에서는 클라이언트 코드에 노출하는 방식을 사용하세요. `crypto.randomUUID()`는 보안 컨텍스트가 필요합니다. HTTPS와 `localhost`에서는 동작하지만 일반 HTTP로 접속한 LAN 주소에서는 동작하지 않습니다.
</Note>

## 에러 처리

| HTTP 상태 코드 | 의미 | 조치 |
|----------------|------|------|
| `400` | 잘못된 요청, 처리가 끝나지 않은 주문을 다운로드할 때의 `ORDER_NOT_COMPLETED`, 또는 보관 기간이 지난 `ORDER_EXPIRED` | 파라미터와 파일 확장자를 확인하세요. `complete`가 된 뒤 다운로드하세요. 만료된 주문은 다운로드할 수 없습니다 |
| `401` | 인증 실패 | API 키 확인 |
| `409` | `WATERMARK_V2_CONFLICT`: 이미 사용한 `idempotencyKey`로 본문이 다른 요청을 보냄 | 새 주문에는 새 `idempotencyKey`를 사용하세요 |
| `429` | 레이트 리밋, 또는 요금제 사용량 소진 시 `PLAN_LIMIT_EXCEEDED` | `code` 값을 확인하세요. 레이트 리밋은 재시도로 풀리지만 `PLAN_LIMIT_EXCEEDED`는 풀리지 않으므로 요금제를 업그레이드해야 합니다 |
| `503` | `WATERMARK_V2_UNAVAILABLE`: 워터마크 처리를 일시적으로 사용할 수 없음 | 같은 `idempotencyKey`로 잠시 후 다시 시도하세요 |

전체 에러 코드는 [에러 코드](/ko/errors) 페이지를 참고하세요.

## v2에서 v3로 마이그레이션

v3의 요청 본문은 v2와 형태가 같습니다. 대부분은 엔드포인트 경로와 결과를 읽는 방식만 바꾸면 됩니다.

<Warning>
  **v3 워터마크 검출은 v2로 삽입한 워터마크를 검출할 수 없습니다.** 엔드포인트만 v3로 바꿔도 기존 v2 워터마크 이미지는 검출되지 않으며, v2 지원이 종료된 뒤 v2 검출을 위한 예외도 제공하지 않습니다.
</Warning>

| | v2 | v3 |
|---|---|---|
| 주문 생성 | `POST /api/v2/orders/wtr-embed` | `POST /api/v3/orders/wtr-embed` |
| 요청 본문 | `files[].fileName`, `originalFileUrl`, `watermarks` | 동일 |
| 크레딧 | — | 이미지·PDF 구분 없이 워터마크 문구당 1크레딧 |
| 결과 | 주문 전체를 한 번에 다운로드 | 워터마크 문구마다 결과 파일이 하나씩 `result.outputFiles[]`에 생김 |
| 주문 조회 | `GET /api/v2/orders/{orderId}` (deprecated) | [`GET /api/v3/orders/{orderId}`](/ko/api-reference/orders/get-order-v3) |
| 다운로드 | `GET /api/v2/orders/{orderId}/download` (deprecated, URL 7일 유효) | [`GET /api/v3/orders/{orderId}/download`](/ko/api-reference/orders/download-order-v3): `archiveUrl`과 결과 파일별 URL (최대 1시간 유효) |
| 업로드 URL | 1시간 유효, `refresh-urls`로 갱신 | 900초 유효, `GET /api/v3/orders/{orderId}`를 다시 호출해 새 URL 받기 |
| confirm 단계 | 없음 | 없음 |
| 웹훅 | `order.watermarkEmbed.completed` / `failed` | 이벤트 이름과 `data` 필드 동일 |

달라지지 않는 점: 한 주문에 이미지와 PDF를 섞을 수 있고, `originalFileUrl`을 지정하면 업로드를 건너뛸 수 있으며, confirm 호출 없이 처리가 시작됩니다.

<Warning>
  주문 조회와 다운로드는 v3 엔드포인트를 사용하세요. `GET /api/v3/orders/{orderId}`와 `GET /api/v3/orders/{orderId}/download`는 v2·v3로 만든 주문 모두에 같은 형식으로 동작합니다. deprecated된 `GET /api/v2/orders/{orderId}`는 v3 주문의 공통 필드만 반환하며 결과는 포함하지 않습니다.
</Warning>

**v2 지원 종료 후 동작** (2026년 10월 9일 09:00 KST, 00:00 UTC부터):

- 인증·권한 검사는 지금처럼 먼저 수행하므로 `401`, `403` 오류는 기존과 같습니다.
- 인증을 통과한 v2 워터마크 삽입·검출 요청은 live 키와 `sk_test_` 키 모두 `410 Gone`과 `{ "code": "WATERMARK_V2_API_SUNSET" }`을 받습니다. `Link` 헤더가 v3 엔드포인트를 가리키니 v3로 새로 요청하세요.
- 그때까지 처리를 시작하지 않은 v2 주문은 처리되지 않고 실패로 확정됩니다. 주문 상세(`errors.errorCode`)와 실패 웹훅에 `WATERMARK_V2_API_SUNSET`과 v3 안내 메시지가 담기며, 과금되지 않고 크레딧은 복원됩니다.
- 종료 시각에 이미 처리 중인 주문은 결과 기록까지 마칩니다. 이후 새로 다시 실행하지는 않습니다.
- 기존 v2 주문 조회와 이미 생성된 결과·보고서 다운로드는 기존 보존 기간 안에서 계속 이용할 수 있습니다. v2 보고서를 새로 생성하거나 재생성할 수는 없습니다.

그 전까지 요청·응답 동작은 같고, v2 워터마크 엔드포인트의 모든 응답에 `Deprecation: true`, `Sunset: Fri, 09 Oct 2026 00:00:00 GMT`, `Link` 헤더만 추가됩니다.
