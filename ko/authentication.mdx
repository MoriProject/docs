모든 API 엔드포인트는 **API 키**를 Bearer 토큰 형식으로 전달하여 인증해야 합니다.

## API 키 발급

1. [BIZ MORI 대시보드](https://app.bizmori.com)에 로그인합니다
2. [**API 키**](https://app.bizmori.com/keys)로 이동합니다
3. **신규 발급**을 클릭합니다
4. 키를 복사하여 안전하게 보관합니다. 일반 API 키는 한 번만 표시됩니다.

대시보드에서는 계정과 조직마다 테스트 API 키를 하나씩 자동 발급합니다. 발급된 키는 API 키 페이지에서 다시 조회할 수 있습니다.

<Warning>
  API 키는 계정의 API에 대한 전체 접근 권한을 부여합니다. 클라이언트 코드, 공개 저장소, 버전 관리 시스템에 절대 노출하지 마세요. 환경 변수로 저장하세요.
</Warning>

## 테스트 API 키

처리 서비스를 실제로 실행하지 않고 연동을 검증하려면 자동 발급된 `sk_test_` 접두사의 테스트 API 키를 사용하세요. 계정과 조직마다 테스트 키가 하나씩 발급되며 Dashboard의 API 키 페이지에서 확인할 수 있습니다.

테스트 API 키는 다음과 같이 동작합니다.

- 일반 키와 동일하게 `Authorization: Bearer` 인증을 사용합니다.
- 일반 키와 동일한 주문 생성·업로드·confirm·조회 엔드포인트를 사용합니다.
- Anti-AI, 워터마크, AI Detection 처리를 실행하지 않습니다.
- 외부 처리 서비스를 호출하지 않으며 크레딧을 소모하지 않습니다.
- 테스트 주문과 운영 주문을 분리합니다.
- 다운로드 가능한 결과 파일을 만들지 않습니다.

영속 테스트 주문에서는 응답의 업로드 URL이 BIZ MORI 테스트 업로드 경로를 가리킵니다. 서버는 요청 스트림을 소비해 업로드 완료만 기록하고 파일 내용은 폐기합니다. Anti-AI 업로드 모드와 AI Detection은 confirm 호출이 필요하며, 워터마크 삽입·검출은 업로드가 끝나면 시작합니다.

테스트 주문은 `pending`, `inProgress`, `complete` 또는 `failed` 상태로 전이됩니다. 일반 주문 API로 테스트 주문 목록·상세·통계를 조회할 수 있습니다. 결과 파일을 만들지 않으므로 다운로드 요청은 `404 PROCESSED_FILE_NOT_FOUND`를 반환합니다. 테스트 키는 테스트 웹훅 endpoint를 관리할 수 없습니다. 전체 동작과 예시는 [테스트 API 키](/ko/test-api-keys)를 참고하세요.

## API 키 사용 방법

모든 요청에서 `Authorization: Bearer` 헤더로 API 키를 전달합니다:

<CodeGroup>
```bash cURL
curl -X POST https://api.bizmori.com/api/v2/orders/anti-ai \
  -H "Authorization: Bearer YOUR_API_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"idempotencyKey": "unique-key", "files": [{"fileName": "image.jpg"}]}'
```

```javascript Node.js
const response = await fetch('https://api.bizmori.com/api/v2/orders/anti-ai', {
  method: 'POST',
  headers: {
    'Authorization': 'Bearer YOUR_API_TOKEN',
    'Content-Type': 'application/json',
  },
  body: JSON.stringify({
    idempotencyKey: 'unique-key',
    files: [{ fileName: 'image.jpg' }],
  }),
});

const data = await response.json();
```

```python Python
import requests

response = requests.post(
    'https://api.bizmori.com/api/v2/orders/anti-ai',
    headers={
        'Authorization': 'Bearer YOUR_API_TOKEN',
    },
    json={
        'idempotencyKey': 'unique-key',
        'files': [{'fileName': 'image.jpg'}],
    },
)
data = response.json()
```

```php PHP
<?php

curl_setopt_array($ch, [
```


```go Go
package main

import (
	"bytes"
	"encoding/json"

)

func main() {
	body, _ := json.Marshal(map[string]any{
		"idempotencyKey": "unique-key",
```

## 멱등성 (Idempotency)

모든 주문 생성 엔드포인트는 `idempotencyKey` 파라미터를 지원합니다. 동일한 키로 중복 요청을 보내면 새 주문을 생성하는 대신 **기존 주문을 반환**합니다. 네트워크 재시도 시 이중 처리를 방지할 수 있습니다.

```json
{
  "idempotencyKey": "01960d3e-a4f2-7b3c-8a1d-4c7e2f9b0a3d",
  "files": [...]
}
```

**UUID v7**을 사용하는 것을 권장합니다. 비즈니스 로직에서 파생된 결정론적 키(예: `user-{id}-batch-{timestamp}`)도 사용할 수 있습니다.
