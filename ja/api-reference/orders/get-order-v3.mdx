注文のステータスを確認し、結果を読み取るときにこのエンドポイントを使用します。Anti-AI、AI Detection、watermark 埋め込み、watermark 検出のすべての注文を、v2 と v3 のどちらで作成したかに関係なく取得できます。トップレベルのフィールドはすべての注文で同じで、`type` によって `result` だけが変わります。

<Warning>
  2026 年 10 月 8 日にレスポンスの形式が変わりました。このエンドポイントから `files`、`outputs`、トップレベルの `reports`、`fileCount`、`statusCode` を読み取っている場合は、[以前のレスポンスからの変更](#以前のレスポンスからの変更)を確認してください。
</Warning>

## 共通フィールド

| フィールド | 型 | 説明 |
|------------|----|------|
| `type` | string | `antiAi`、`aiDetection`、`watermarkEmbed`、`watermarkExtract` のいずれか |
| `orderId` | string | 注文 ID |
| `orderName` | string \| null | 注文名 |
| `channel` | string | `api` または `web` |
| `status` | string | [ステータス](#ステータス)の 5 つの値のいずれか |
| `createdAt`, `updatedAt` | string | ISO 8601 の日時 |
| `expiresAt` | string \| null | 注文ファイルが削除される日時 |
| `retentionDays` | integer \| null | ファイルの保管期間（日、7 または 30） |
| `thumbnailImageUrl` | string \| null | サムネイル画像の URL |
| `processingDelayed` | boolean | v3 で作成した watermark 注文が手動復旧を待っているときに `true`。それ以外の注文では常に `false` |
| `errors` | object \| null | 失敗した注文の `{ errorCode, errorMessage }`。それ以外は `null` |
| `inputFiles` | array | 入力ファイル。[入力ファイル](#入力ファイル)を参照 |
| `result` | object \| null | 注文の種類ごとの結果。[注文の種類ごとの結果](#注文の種類ごとの結果)を参照 |

## ステータス

| `status` | 意味 | `result` |
|----------|------|----------|
| `pending` | ファイルのアップロード待ち。`inputFiles[].uploadUrl` があります | `null` |
| `inProgress` | 処理中 | `null` |
| `complete` | 完了 | オブジェクト |
| `failed` | 処理に失敗。理由は `errors` にあります | `null` |
| `expired` | 保管期限が過ぎ、ファイルは削除済み。URL は発行しません | `null` |

v2 で作成した watermark 検出注文のうち、保存されたステータスが `detected` または `undetected` の注文は `complete` を返します。判定は `result.detectionStatus` から読み取ってください。

## 入力ファイル

`inputFiles[]` の各項目には `fileId` と `fileName` があり、注文作成リクエストの順に並びます。次の 2 つのキーは該当する場合だけ含まれます。該当しない場合は `null` ではなく、キー自体がありません。

- `role` は `watermarkExtract` の注文にだけ含まれます。`original` は watermark を埋め込んだ元のファイル、`query` は検査するファイルです。
- `uploadUrl` は `status` が `pending` で、そのファイルがまだアップロード待ちのときだけ含まれます。この URL にファイルを PUT してください。アップロード URL の期限が切れた場合は、このエンドポイントを再度呼び出すと新しい URL を取得できます。

このレスポンスと[ダウンロードのレスポンス](/ja/api-reference/orders/download-order-v3)のすべての `fileId` は、`"11"` のような数字だけの文字列です。`-` などの区切り文字は含みません。

## 注文の種類ごとの結果

`result` は `status` が `complete` のときだけオブジェクトです。キーは常にあり、それ以外のステータスでは `null` です。

<Tabs>
  <Tab title="Anti-AI">
    `result.outputFiles[]` には、入力ファイルごとに結果ファイルが 1 つずつあります。

    | フィールド | 型 | 説明 |
    |------------|----|------|
    | `fileId` | string | 結果ファイル ID。[ダウンロードのレスポンス](/ja/api-reference/orders/download-order-v3)の `files[].fileId` と値・順序が一致 |
    | `fileName` | string \| null | 結果ファイル名 |
    | `inputFileId` | string | 元の入力ファイルの `inputFiles[].fileId` |
  </Tab>
  <Tab title="watermark 埋め込み">
    `result.outputFiles[]` には、埋め込んだ watermark テキストごとに結果ファイルが 1 つずつあります。v3 の注文で 1 つの入力ファイルに複数のテキストを埋め込むと、それらの結果ファイルは同じ `inputFileId` を持ちます。

    | フィールド | 型 | 説明 |
    |------------|----|------|
    | `fileId` | string | 結果ファイル ID。[ダウンロードのレスポンス](/ja/api-reference/orders/download-order-v3)の `files[].fileId` と値・順序が一致 |
    | `fileName` | string \| null | 結果ファイル名 |
    | `inputFileId` | string | 元の入力ファイルの `inputFiles[].fileId` |
    | `watermarkText` | string | この結果ファイルに埋め込んだテキスト |
  </Tab>
  <Tab title="watermark 検出">
    | フィールド | 型 | 説明 |
    |------------|----|------|
    | `detectionStatus` | string | 判定。下の表を参照 |
    | `watermarkText` | string \| null | 検出された watermark の埋め込みテキスト。`detectionStatus` が `detected` でなければ `null`。v3 の注文では、呼び出し元のアカウントが埋め込み、発行記録がちょうど 1 件のときだけ返します |
    | `reportSupported` | boolean | この結果から[レポートを作成](/ja/api-reference/reports/create-report)できるかどうか。v2 の注文と PDF からキャプチャした画像は `false` |
    | `reports` | array | この注文で依頼したレポートごとの `{ locale, status }`。v2 の注文では常に空の配列 |

    | `detectionStatus` | 意味 |
    |-------------------|------|
    | `detected` | watermark が見つかった |
    | `undetected` | 最後まで検査したが watermark はなかった |
    | `inconclusive` | 候補はあるが、確信度の基準に届かなかった |
    | `unsupported` | 処理できない入力。クレジットは返却されます |
    | `error` | 検出処理に失敗。watermark なしとは異なります |
  </Tab>
  <Tab title="AI Detection">
    | フィールド | 型 | 説明 |
    |------------|----|------|
    | `verdict` | string \| null | `probability` に基づく判定。下の表を参照。`probability` が `null` なら `null` |
    | `probability` | number \| null | 画像が AI で生成された確率（0〜1） |
    | `options` | object \| null | 注文作成時に設定した `generateHeatmap`、`generateOverlay`、`generateThumbnail` |
    | `originalImageUrl` | string \| null | 元の画像の URL（1 時間有効） |
    | `heatmapUrl` | string \| null | ヒートマップ画像の URL（1 時間有効）。`generateHeatmap` を使わなかった注文では `null` |
    | `overlayUrl` | string \| null | ヒートマップのオーバーレイ画像の URL（1 時間有効）。`generateOverlay` を使わなかった注文では `null` |

    | `verdict` | 確率の範囲 | 意味 |
    |-----------|------------|------|
    | `likely_real` | < 0.25 | AI 生成ではない可能性が高い |
    | `uncertain_real` | 0.25 – 0.5 | AI 生成ではない可能性がある |
    | `uncertain_ai` | 0.5 – 0.75 | AI 生成の可能性がある |
    | `likely_ai` | ≥ 0.75 | AI 生成の可能性が高い |
  </Tab>
</Tabs>

- **Pending**: まだアップロード待ちのファイルにだけ `uploadUrl` があります。watermark 埋め込み、Anti-AI、AI Detection の注文には `role` がありません。
- **Failed**: `errors` に理由があり、`result` は `null` です。`errorMessage` はエラーコードごとの固定の韓国語の案内文です。
- **Expired**: 保管期限が過ぎた注文も取得できますが、`result` は `null` で、URL は発行しません。[ダウンロード](/ja/api-reference/orders/download-order-v3)は `400 ORDER_EXPIRED` を返します。

## 以前のレスポンスからの変更

2026 年 10 月 8 日から、このエンドポイントは上記の形式で応答します。後方互換性のない変更です。

| 以前のレスポンス | 現在 |
|------------------|------|
| `files[]`（v3 の watermark 注文） | `inputFiles[]`。`uploadUrl` は `pending` の注文にだけあります |
| `outputs[]`（v3 の watermark 注文） | `result.outputFiles[]`。`outputIndex`、`status`、`mediaKind` は返しません |
| `"601-1"` 形式の結果 `fileId` | `"201"` のような数字の文字列 |
| トップレベルの `reports[]` | `result.reports[]` |
| `detectionStatus: "not_detected"` | `"undetected"` |
| `fileCount` | `inputFiles.length` |
| `statusCode`（AI Detection） | `result.verdict` |
| `statusCode` と `status: "detected"` / `"undetected"`（v2 の watermark 検出） | `status: "complete"` と `result.detectionStatus` |
| `watermarks[]`（v2 の watermark 埋め込み） | `result.outputFiles[].watermarkText` |
| トップレベルの `watermarkText`、`probability`、`options`、`originalImageUrl`、`heatmapUrl`、`overlayUrl` | `result` の中に移動 |

非推奨（deprecated）の [`GET /api/v2/orders/{orderId}`](/ja/api-reference/orders/get-order) は、以前のレスポンスをそのまま返します。

## テストキー

`sk_test_` キーで呼び出すと、同じキーで作成したテスト注文だけを上記の形式で返します。テスト注文のステータスの変化は[テスト API キー](/ja/test-api-keys)を参照してください。
