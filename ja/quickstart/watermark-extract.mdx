このガイドでは、v3 API でファイルに不可視 watermark が含まれているかを確認する手順を、注文の作成から結果の確認、PDF レポートのダウンロードまで説明します。

すべてのエンドポイントは純粋な HTTPS と JSON を使用するため、サーバーからでもブラウザからでも同じように呼び出せます。各ステップには **React** タブがあり、そのままコピーして使える[完全なコンポーネント](#react-完全なサンプル)はページ下部にあります。

<Warning>
  v2 の watermark 抽出エンドポイント（`POST /api/v2/orders/wtr-extract`）は 2026 年 10 月 9 日 09:00 KST（00:00 UTC）にサポートを終了する予定です。このガイドは v3 API を前提に説明します。すでに v2 を使用している場合は、[v2 から v3 への移行](#v2-から-v3-への移行)を参照してください。
</Warning>

<Warning>
  **v3 の watermark 抽出では、v2 で埋め込んだ watermark を検出できません。** エンドポイントを v3 に切り替えるだけでは既存の v2 watermark 画像は検出されず、v2 のサポート終了後に v2 の検出を例外的に受け付けることもありません。
</Warning>

## 事前準備

- BIZ MORI API キー（[こちらから発行](https://app.bizmori.com/keys)）
- watermark を埋め込んだ**元のファイル** — watermark が埋め込まれた結果ファイルではなく、[watermark の埋め込み](/ja/quickstart/watermark-embed)で送信したファイルです
- **検査するファイル**:
  - 元のファイルが画像（`jpg`、`jpeg`、`png`、`webp`、`bmp`、`tif`、`tiff`）の場合、検査するファイルも画像です。
  - 元のファイルが PDF の場合、検査するファイルは PDF、またはその PDF をキャプチャした PNG・JPEG 画像です。

<Info>
  自動発行される [`sk_test_` キー](/ja/test-api-keys)を使うと、実際の watermark 検出を行わず、クレジットも消費せずに v3 のフロー全体を検証できます。テストアップロードはファイルの内容を破棄し、結果は検査するファイルの名前で決まります。`_detected` を含めば `detected`、それ以外は `not_detected` になり、どちらかのファイル名に `_fail` が含まれると注文は失敗します。
</Info>

## 処理の流れ

1. 元のファイルと検査するファイルの名前を指定して**注文を作成**します。
2. レスポンスのプリサインド URL に**2 つのファイルを `PUT` でアップロード**します。両方のアップロードが終わると検出が自動的に始まり、confirm ステップはありません。
3. `GET /api/v3/orders/{orderId}` をポーリングするか [Webhook](/ja/webhooks) を受信して、**結果を確認**します。
4. 必要に応じて、結果の **PDF レポートを作成**します。

## ステップ2: 2 つのファイルのアップロード

各ファイルをプリサインド `uploadUrl` に PUT でアップロードします。ストレージへの直接アップロードなので、**Authorization ヘッダーは不要です**。

`Content-Type` ヘッダーには、ファイルの拡張子に合った値を指定してください。プリサインド URL はこのタイプで署名されているため、ほかの値を送るとアップロードは拒否されます。

| 拡張子 | `Content-Type` |
|--------|----------------|
| `jpg`、`jpeg` | `image/jpeg` |
| `png` | `image/png` |
| `webp` | `image/webp` |
| `bmp` | `image/bmp` |
| `tif`、`tiff` | `image/tiff` |
| `pdf` | `application/pdf` |

<CodeGroup>
```bash cURL
# files[0]: 元のファイル
curl -X PUT "https://s3.ap-northeast-2.amazonaws.com/...original..." \
  -H "Content-Type: image/png" \
  --data-binary @campaign.png

# files[1]: 検査するファイル
curl -X PUT "https://s3.ap-northeast-2.amazonaws.com/...checked..." \
  -H "Content-Type: image/png" \
  --data-binary @suspect.png
```

```javascript Node.js
import { readFile } from 'node:fs/promises';

async function putFile(uploadUrl, path, contentType) {
  const res = await fetch(uploadUrl, {
    method: 'PUT',
    headers: { 'Content-Type': contentType },
    body: await readFile(path),
  });
  if (!res.ok) throw new Error(`UPLOAD_FAILED_${res.status}`);
}

await putFile(order.files[0].uploadUrl, 'campaign.png', 'image/png'); // 元のファイル
await putFile(order.files[1].uploadUrl, 'suspect.png', 'image/png'); // 検査するファイル
```

```jsx React
// プリサインド URL は拡張子に合ったタイプで署名されているため、
// `file.type` ではなくファイル名から Content-Type を決めます。
const CONTENT_TYPES = {
  jpg: 'image/jpeg', jpeg: 'image/jpeg', png: 'image/png', webp: 'image/webp',
  bmp: 'image/bmp', tif: 'image/tiff', tiff: 'image/tiff', pdf: 'application/pdf',
};
const contentTypeOf = (name) => CONTENT_TYPES[name.split('.').pop().toLowerCase()];

// fetch() はアップロードの進捗を通知できないため、PUT には XMLHttpRequest を使用します。
function putFile(file, uploadUrl, onProgress) {
  return new Promise((resolve, reject) => {
    const xhr = new XMLHttpRequest();
    xhr.open('PUT', uploadUrl);
    xhr.setRequestHeader('Content-Type', contentTypeOf(file.name));

    xhr.upload.onprogress = (event) => {
      if (event.lengthComputable) onProgress(event.loaded / event.total);
    };
    xhr.onload = () =>
      xhr.status < 300 ? resolve() : reject(new Error(`UPLOAD_FAILED_${xhr.status}`));
    xhr.onerror = () => reject(new Error('UPLOAD_NETWORK_ERROR'));

    xhr.send(file);
  });
}

// files[0] は元のファイル、files[1] は検査するファイルです。
await Promise.all([
  putFile(originalFile, order.files[0].uploadUrl, () => {}),
  putFile(checkedFile, order.files[1].uploadUrl, (ratio) => setProgress(ratio)),
]);
```

</Note>

## ステップ3: 結果の確認

`status` が `complete` になるまで注文をポーリングし、`result` を読み取ってください。ポーリングの代わりに [Webhook](/ja/webhooks) を設定すると、`order.watermarkExtract.completed` または `order.watermarkExtract.failed` を受信できます。

<CodeGroup>
```bash cURL
curl https://api.bizmori.com/api/v3/orders/1234567891 \
  -H "Authorization: Bearer YOUR_API_KEY"
```


```jsx React
const sleep = (ms) => new Promise((resolve) => setTimeout(resolve, ms));

// 待ち時間が長くなるほどポーリング間隔を広げます。すぐ終わる処理は素早く応答し、
// 時間のかかる処理で API を叩き続けないようにします。無限にポーリングせず、10 分で諦めます。
// ポーリングは `status` で判断し、検出結果は `result` から読み取ります。
async function pollOrder(orderId, { onStatus, timeoutMs = 10 * 60 * 1000 } = {}) {
  const deadline = Date.now() + timeoutMs;
  let delay = 2000;

  while (Date.now() < deadline) {
    const order = await api(`/orders/${orderId}`);
    onStatus?.(order.status);
    if (['complete', 'failed', 'expired'].includes(order.status)) return order;

    await sleep(delay);
    delay = Math.min(delay * 1.5, 15000);
  }
  throw new Error('ORDER_POLL_TIMEOUT');
}
```

`status` で注文の完了を確認した後、`result.detectionStatus` で結果を読み取ってください。

| `status` | 意味 |
|----------|------|
| `pending` | ファイルのアップロード待ち |
| `inProgress` | 検出処理中 |
| `complete` | 完了 — `result` を確認してください |
| `failed` | 検出失敗。消費したクレジットは戻ります |
| `expired` | 保管期間が終了し、ファイルが削除された |

| `result.detectionStatus` | 意味 |
|--------------------------|------|
| `detected` | watermark が見つかった |
| `not_detected` | ファイル全体を検査したが、watermark はなかった |
| `inconclusive` | 候補はあるが、判断できるほどの確度がない |
| `unsupported` | 処理できない入力。クレジットは戻ります |
| `error` | 検出処理に失敗。「watermark なし」とは異なります。クレジットは戻ります |

- `result.watermarkText` は埋め込んだ文言です。結果が `detected` で、自分のアカウントが埋め込み、埋め込み記録がちょうど 1 件のときだけ返されます。それ以外は `null` です。
- `result.reportSupported` は、この結果で PDF レポートを作成できるかを示します。PDF をキャプチャした画像を検査した場合は `false` です。
- `processingDelayed` が `true` の場合、自動再試行をすべて使い切り、手動での復旧を待っている状態です。注文は `inProgress` のままなので、ポーリングを続けるか Webhook を待ってください。

<Note>
  Webhook のペイロードは v2 のフィールド名をそのまま使います。`order.watermarkExtract.completed` は結果を `statusCode` で通知し、`not_detected` の代わりに `undetected` を使います。`watermarkFound` と `watermarkInfo.text` も含まれます。ペイロード全体は [Webhook](/ja/webhooks) を参照してください。
</Note>

## ステップ4: PDF レポートの作成（任意）

`result.reportSupported` が `true` の場合、結果の PDF レポートを韓国語（`ko-KR`）、英語（`en-US`）、日本語（`ja-JP`）で作成できます。PDF ファイルのレポートは `ko-KR` のみ対応しています。レポートは 1 クレジットを消費し、作成に成功した場合にのみ差し引かれます。

```javascript Node.js
async function createReport(orderId, locale) {
  const created = await fetch(`${API_BASE}/orders/${orderId}/reports`, {
    method: 'POST',
    headers: { ...headers, 'Content-Type': 'application/json' },
    body: JSON.stringify({ locale }),
  });
  if (!created.ok) throw new Error((await created.json()).code);

  for (let delay = 2000; ; delay = Math.min(delay * 1.5, 15000)) {
    const res = await fetch(`${API_BASE}/orders/${orderId}/reports/${locale}`, { headers });
    const { data: report } = await res.json();
    if (report.status === 'completed') return report.download.url;
    if (report.status === 'failed') throw new Error(report.failure.code);
    await sleep(delay);
  }
}

const reportUrl = await createReport(order.orderId, 'ja-JP');
```

```jsx WatermarkExtractChecker.jsx
  // 再試行では呼び出し元の idempotency key をそのまま再利用するため、再試行した作成リクエストが
  // 2 つ目の注文を作ることはありません。認証失敗は `AUTH_*` コードとして返り、
  // 再試行しても解決しないため、下の throw に進みます。
  for (let attempt = 0; ; attempt++) {
    const res = await fetch(`${API_BASE}${path}`, {
      method,
      headers: {
        Authorization: `Bearer ${API_KEY}`,
        ...(body && { 'Content-Type': 'application/json' }),
      },
      body: body && JSON.stringify({ idempotencyKey, ...body }),
    });

    if (!res.ok) {
      const { code } = await res.json().catch(() => ({}));
      // 429 には 2 つのケースがあります：一時的なレート制限と、プランの利用量を使い切り
      // 再試行しても解消しない PLAN_LIMIT_EXCEEDED です。
      if (res.status === 429 && code !== 'PLAN_LIMIT_EXCEEDED' && attempt < 3) {
        await sleep(2 ** attempt * 1000);
        continue;
      }
      throw new Error(code ?? `HTTP_${res.status}`);
    }
    return (await res.json()).data;
  }
}

function putFile(file, uploadUrl, onProgress) {
  return new Promise((resolve, reject) => {
    const xhr = new XMLHttpRequest();
    xhr.open('PUT', uploadUrl);
    xhr.setRequestHeader('Content-Type', contentTypeOf(file.name));

    xhr.upload.onprogress = (event) => {
      if (event.lengthComputable) onProgress(event.loaded / event.total);
    };
    xhr.onload = () =>
      xhr.status < 300 ? resolve() : reject(new Error(`UPLOAD_FAILED_${xhr.status}`));
    xhr.onerror = () => reject(new Error('UPLOAD_NETWORK_ERROR'));

    xhr.send(file);
  });
}

async function poll(fetchOnce, isDone, { timeoutMs = 10 * 60 * 1000 } = {}) {
  const deadline = Date.now() + timeoutMs;
  let delay = 2000;

  while (Date.now() < deadline) {
    const value = await fetchOnce();
    if (isDone(value)) return value;

    await sleep(delay);
    delay = Math.min(delay * 1.5, 15000);
  }
  throw new Error('POLL_TIMEOUT');
}

export default function WatermarkExtractChecker() {
  const [originalFile, setOriginalFile] = useState(null);
  const [checkedFile, setCheckedFile] = useState(null);
  const [progress, setProgress] = useState(0);
  const [status, setStatus] = useState('idle');
  const [order, setOrder] = useState(null);
  const [error, setError] = useState(null);
  const inFlight = useRef(false);

  const busy = status !== 'idle' && status !== 'complete';
  const canSubmit =
    originalFile !== null &&
    checkedFile !== null &&
    contentTypeOf(originalFile.name) !== undefined &&
    contentTypeOf(checkedFile.name) !== undefined &&
    !busy;

  async function checkWatermark(event) {
    event.preventDefault();
    if (inFlight.current || !canSubmit) return;
    inFlight.current = true;

    // 選択内容を固定します。リクエスト中にユーザーがファイルを変更しても、
    // 各ファイルは自分のアップロード URL と対応したままでなければなりません。
    const original = originalFile;
    const checked = checkedFile;
    setError(null);
    setOrder(null);
    setProgress(0);

    try {
      setStatus('creating order');
      const created = await api('/orders/wtr-extract', {
        method: 'POST',
        idempotencyKey: crypto.randomUUID(),
        body: { file: { fileName: checked.name, originalFile: { fileName: original.name } } },
      });
      setOrder(created);

      setStatus('uploading');
      // files[0] は元のファイル、files[1] は検査するファイルです。
      await Promise.all([
        putFile(original, created.files[0].uploadUrl, () => {}),
        putFile(checked, created.files[1].uploadUrl, setProgress),
      ]);

      const finished = await poll(
        () => api(`/orders/${created.orderId}`),
        (current) => {
          setStatus(current.status);
          return ['complete', 'failed', 'expired'].includes(current.status);
        },
      );
      if (finished.status !== 'complete') throw new Error(`ORDER_${finished.status.toUpperCase()}`);

      setOrder(finished);
      setStatus('complete');
    } catch (caught) {
      setError(caught.message);
      setStatus('idle');
    } finally {
      inFlight.current = false;
    }
  }

  // レポートの URL は 300 秒で期限切れになるため、押すたびに新しく取得します。
  async function openReport() {
    try {
      await api(`/orders/${order.orderId}/reports`, { method: 'POST', body: { locale: REPORT_LOCALE } });
      const report = await poll(
        () => api(`/orders/${order.orderId}/reports/${REPORT_LOCALE}`),
        (current) => ['completed', 'failed'].includes(current.status),
      );
      if (report.status === 'failed') throw new Error(report.failure.code);
      window.location.assign(report.download.url);
    } catch (caught) {
      setError(caught.message);
    }
  }

  const result = status === 'complete' ? order?.result : null;

  return (
    <form onSubmit={checkWatermark}>
      <label>
        元のファイル
        <input
          type="file"
          accept={ACCEPT_FORMATS}
          disabled={busy}
          onChange={(event) => setOriginalFile(event.target.files[0] ?? null)}
        />
      </label>
      <label>
        検査するファイル
        <input
          type="file"
          accept={ACCEPT_FORMATS}
          disabled={busy}
          onChange={(event) => setCheckedFile(event.target.files[0] ?? null)}
        />
      </label>
      <button type="submit" disabled={!canSubmit}>
        watermark を確認
      </button>

      {status !== 'idle' && <p>ステータス: {status}</p>}
      {status === 'uploading' && <p>アップロード中: {Math.round(progress * 100)}%</p>}

      {/* `status` は注文が終わったか、`result.detectionStatus` は何が見つかったかを示します。 */}
      {result && (
        <p>
          {RESULT_LABELS[result.detectionStatus]}
          {result.watermarkText && <strong> {result.watermarkText}</strong>}
        </p>
      )}
      {result?.reportSupported && (
        <button type="button" onClick={openReport}>
          PDF レポートをダウンロード
        </button>
      )}
      {error && <p role="alert">失敗: {error}{order && ` (orderId: ${order.orderId})`}</p>}
    </form>
  );
}
```

<Note>
  `import.meta.env.VITE_MORI_API_KEY` は Vite の構文です。Next.js では `process.env.NEXT_PUBLIC_MORI_API_KEY` を、その他のバンドラーではクライアントコードに公開する方法を使用してください。`crypto.randomUUID()` にはセキュアコンテキストが必要です。HTTPS と `localhost` では動作しますが、通常の HTTP でアクセスする LAN アドレスでは動作しません。
</Note>

公開される結果には `detectionStatus`、`reportSupported`、`watermarkText` のみが含まれ、watermark ID（MID）は含まれません。

## エラー処理

| HTTP ステータスコード | 意味 | 対応 |
|----------------|------|------|
| `400` | 不正なリクエスト、`REPORT_LOCALE_UNSUPPORTED`、または保管期間を過ぎた `ORDER_EXPIRED` | パラメータ、ファイルの拡張子、レポートの locale を確認してください |
| `401` | 認証失敗 | API キーを確認 |
| `404` | `ORDER_NOT_FOUND`、またはリクエストしていない locale の `REPORT_NOT_FOUND` | 注文 ID を確認し、レポートは作成してから取得してください |
| `409` | 使用済みの `idempotencyKey` による `WATERMARK_V2_CONFLICT`、またはレポートを作成できない結果の `REPORT_NOT_AVAILABLE` | 新しい `idempotencyKey` を使うか、`result.reportSupported` を確認してください |
| `429` | レート制限、またはプラン使用量の超過時は `PLAN_LIMIT_EXCEEDED` | `code` を確認してください。レート制限は再試行で解消しますが、`PLAN_LIMIT_EXCEEDED` は解消しないためプランのアップグレードが必要です |
| `503` | watermark 処理またはレポート作成が一時的に利用できない | しばらくしてから再試行してください |

エラーコードの一覧は、[エラーコード](/ja/errors) ページを参照してください。

## v2 から v3 への移行

v3 では検査するファイルを常に元のファイルと比較するため、リクエストで両方のファイルを指定します。

<Warning>
  **v3 の watermark 抽出では、v2 で埋め込んだ watermark を検出できません。** エンドポイントを v3 に切り替えるだけでは既存の v2 watermark 画像は検出されず、v2 のサポート終了後に v2 の検出を例外的に受け付けることもありません。
</Warning>

| | v2 | v3 |
|---|---|---|
| 注文の作成 | `POST /api/v2/orders/wtr-extract` | `POST /api/v3/orders/wtr-extract` |
| 元のファイル | 任意（`includeOriginal`）、画像のみ | すべての注文で必須、画像と PDF の両方に対応 |
| リクエスト本文 | `file.fileName`、`file.includeOriginal`、`file.originalFile` | `file.fileName` と `file.originalFile.fileName`。`includeOriginal` はなし |
| アップロード | 1 ファイル、`includeOriginal` 使用時は 2 ファイル | 常に 2 ファイル：`files[0]` は元のファイル、`files[1]` は検査するファイル |
| 結果の取得 | `GET /api/v2/orders/{orderId}` → `statusCode`（`detected` / `undetected`） | [`GET /api/v3/orders/{orderId}`](/ja/api-reference/orders/get-order-v3) → `result.detectionStatus`（5 種類）、`result.watermarkText`、`result.reportSupported` |
| クレジット | — | 画像・PDF を問わず注文ごとに 1 クレジット。`unsupported`・`error` の結果は返還 |
| PDF レポート | なし | レポートの[作成](/ja/api-reference/reports/create-report)・[取得](/ja/api-reference/reports/get-report) |
| confirm ステップ | なし | なし |
| Webhook | `order.watermarkExtract.completed` / `failed` | イベント名と `data` フィールドは同じ。`statusCode` に `inconclusive`、`unsupported`、`error` が追加 |

<Warning>
  v3 で作成した注文は v3 のエンドポイントで扱ってください。`GET /api/v2/orders/{orderId}` は v3 注文の共通フィールドだけを返し、`result` は含みません。逆に `GET /api/v3/orders/{orderId}` は v2 の注文に対して `404 ORDER_NOT_FOUND` を返します。
</Warning>

**v2 のサポート終了後の動作**（2026 年 10 月 9 日 09:00 KST、00:00 UTC から）:

- 認証・権限の確認はこれまでどおり先に行われるため、`401`・`403` エラーは従来と同じです。
- 認証を通過した v2 の watermark 埋め込み・抽出リクエストには、本番キーと `sk_test_` キーのどちらでも `410 Gone` と `{ "code": "WATERMARK_V2_API_SUNSET" }` が返されます。`Link` ヘッダーが v3 エンドポイントを示すので、v3 で新しくリクエストしてください。
- その時点までに処理が始まっていない v2 注文は、処理されずに失敗として確定します。注文の詳細（`errors.errorCode`）と失敗 Webhook には `WATERMARK_V2_API_SUNSET` と v3 への案内メッセージが含まれ、課金されずクレジットは戻ります。
- 終了時点ですでに処理中の注文は、結果の記録まで完了します。その後に改めて実行されることはありません。
- 既存の v2 注文の取得と、作成済みの結果・レポートのダウンロードは、既存の保管期間内であれば引き続き利用できます。v2 レポートの新規作成・再作成はできません。

それまではリクエストとレスポンスの動作は変わらず、これらのエンドポイントのすべてのレスポンスに `Deprecation: true`、`Sunset: Fri, 09 Oct 2026 00:00:00 GMT`、`Link` ヘッダーが付くだけです。
