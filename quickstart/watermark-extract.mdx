This guide walks you through checking a file for an invisible watermark with the v3 API — from creating an order to reading the result and downloading a PDF report.

Every endpoint here is plain HTTPS and JSON, so the same calls work from a server or straight from the browser. Each step includes a **React** tab, and a [full copy-paste component](#full-react-example) is at the bottom of the page.

<Warning>
  The v2 watermark extract endpoint (`POST /api/v2/orders/wtr-extract`) ends support on October 7, 2026. This guide uses the v3 API. If you already call v2, see [Migrating from v2 to v3](#migrating-from-v2-to-v3).
</Warning>

## Prerequisites

- A BIZ MORI API key ([get one here](https://app.bizmori.com/keys))
- The **original file** the watermark was embedded into — the file you sent to [watermark embed](/quickstart/watermark-embed), not the watermarked output
- The **file to check**:
  - If the original is an image (`jpg`, `jpeg`, `png`, `webp`, `bmp`, `tif`, or `tiff`), the file to check is an image.
  - If the original is a PDF, the file to check is a PDF, or a PNG or JPEG image captured from it.

<Info>
  Use the automatically issued [`sk_test_` key](/test-api-keys) to exercise the whole v3 flow without running watermark extraction or consuming credits. Test uploads discard file contents, and the name of the file to check selects the result: `_detected` returns `detected`, anything else returns `not_detected`, and `_fail` on either file fails the order.
</Info>

## How it works

1. **Create an order** with the names of the original file and the file to check.
2. **Upload both files** with `PUT` to the presigned URLs in the response. Extraction starts automatically once both are uploaded — there is no confirm step.
3. **Read the result** by polling `GET /api/v3/orders/{orderId}` or by receiving a [webhook](/webhooks).
4. **Create a PDF report** for the result if you need one.

## Step 1: Create an order

Create a watermark extract order. Each order checks one file and uses 1 credit.

<CodeGroup>
```bash cURL
ORDER_IDEMPOTENCY_KEY=$(uuidgen | tr '[:upper:]' '[:lower:]')

  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \

    "idempotencyKey": "'$ORDER_IDEMPOTENCY_KEY'",
```

## Step 2: Upload both files

PUT each file to its presigned `uploadUrl`. This is a direct upload to storage — **no Authorization header needed**.

Send a `Content-Type` header that matches the file extension. The presigned URL is signed for that type, so any other value is rejected.

| Extension | `Content-Type` |
|-----------|----------------|
| `jpg`, `jpeg` | `image/jpeg` |
| `png` | `image/png` |
| `webp` | `image/webp` |
| `bmp` | `image/bmp` |
| `tif`, `tiff` | `image/tiff` |
| `pdf` | `application/pdf` |

<CodeGroup>
```bash cURL
# files[0]: the original file
curl -X PUT "https://s3.ap-northeast-2.amazonaws.com/...original..." \
  -H "Content-Type: image/png" \
  --data-binary @campaign.png

# files[1]: the file to check
curl -X PUT "https://s3.ap-northeast-2.amazonaws.com/...checked..." \
  -H "Content-Type: image/png" \
  --data-binary @suspect.png
```

```javascript Node.js
import { readFile } from 'node:fs/promises';

async function putFile(uploadUrl, path, contentType) {
  const res = await fetch(uploadUrl, {
    method: 'PUT',
    headers: { 'Content-Type': contentType },
    body: await readFile(path),
  });
  if (!res.ok) throw new Error(`UPLOAD_FAILED_${res.status}`);
}

await putFile(order.files[0].uploadUrl, 'campaign.png', 'image/png'); // original
await putFile(order.files[1].uploadUrl, 'suspect.png', 'image/png'); // file to check
```

```jsx React
// The presigned URL is signed for the type that matches the file extension,
// so derive Content-Type from the name instead of trusting `file.type`.
const CONTENT_TYPES = {
  jpg: 'image/jpeg', jpeg: 'image/jpeg', png: 'image/png', webp: 'image/webp',
  bmp: 'image/bmp', tif: 'image/tiff', tiff: 'image/tiff', pdf: 'application/pdf',
};
const contentTypeOf = (name) => CONTENT_TYPES[name.split('.').pop().toLowerCase()];

// fetch() cannot report upload progress, so use XMLHttpRequest for the PUT.
function putFile(file, uploadUrl, onProgress) {
  return new Promise((resolve, reject) => {
    const xhr = new XMLHttpRequest();
    xhr.open('PUT', uploadUrl);
    xhr.setRequestHeader('Content-Type', contentTypeOf(file.name));

    xhr.upload.onprogress = (event) => {
      if (event.lengthComputable) onProgress(event.loaded / event.total);
    };
    xhr.onload = () =>
      xhr.status < 300 ? resolve() : reject(new Error(`UPLOAD_FAILED_${xhr.status}`));
    xhr.onerror = () => reject(new Error('UPLOAD_NETWORK_ERROR'));

    xhr.send(file);
  });
}

// files[0] is the original, files[1] is the file to check.
await Promise.all([
  putFile(originalFile, order.files[0].uploadUrl, () => {}),
  putFile(checkedFile, order.files[1].uploadUrl, (ratio) => setProgress(ratio)),
]);
```

<Note>
  A live `uploadUrl` expires after **900 seconds**. If it expires, call [`GET /api/v3/orders/{orderId}`](/api-reference/orders/get-order-v3) to receive a fresh `uploadUrl` for each file that is still waiting for upload. Upload both files within **12 hours** of creating the order, or the order becomes `failed`. Test keys receive `https://api.bizmori.com/api/v2/test-uploads/{signedToken}` instead, valid for 1 hour; it accepts the same unauthenticated PUT and discards the file contents.
</Note>

## Step 3: Read the result

Poll the order until `status` is `complete`, then read `result`. You can also set up [webhooks](/webhooks) to receive `order.watermarkExtract.completed` or `order.watermarkExtract.failed` instead of polling.

<CodeGroup>
```bash cURL
curl https://api.bizmori.com/api/v3/orders/1234567891 \
  -H "Authorization: Bearer YOUR_API_KEY"
```

```javascript Node.js
const sleep = (ms) => new Promise((resolve) => setTimeout(resolve, ms));

async function waitForOrder(orderId) {
  for (let delay = 2000; ; delay = Math.min(delay * 1.5, 15000)) {
    const res = await fetch(`${API_BASE}/orders/${orderId}`, { headers });
    const { data } = await res.json();
    if (['complete', 'failed', 'expired'].includes(data.status)) return data;
    await sleep(delay);
  }
}

const finished = await waitForOrder(order.orderId);
console.log(finished.result?.detectionStatus, finished.result?.watermarkText);
```

```jsx React
const sleep = (ms) => new Promise((resolve) => setTimeout(resolve, ms));

// Back off as the wait grows: quick answers stay quick, long jobs stop
// hammering the API. Give up after 10 minutes rather than polling forever.
// Poll on `status` — the detection outcome arrives in `result`.
async function pollOrder(orderId, { onStatus, timeoutMs = 10 * 60 * 1000 } = {}) {
  const deadline = Date.now() + timeoutMs;
  let delay = 2000;

  while (Date.now() < deadline) {
    const order = await api(`/orders/${orderId}`);
    onStatus?.(order.status);
    if (['complete', 'failed', 'expired'].includes(order.status)) return order;

    await sleep(delay);
    delay = Math.min(delay * 1.5, 15000);
  }
  throw new Error('ORDER_POLL_TIMEOUT');
}
```

```json

  }

```

Poll `status` to know when the order is done, then read `result.detectionStatus` for the outcome:

| `status` | Meaning |
|----------|---------|
| `pending` | Waiting for file uploads |
| `inProgress` | Extraction running |
| `complete` | Finished — read `result` |
| `failed` | Extraction failed. The used credit is restored |
| `expired` | The retention period ended and the files were deleted |

| `result.detectionStatus` | Meaning |
|--------------------------|---------|
| `detected` | A watermark was found |
| `not_detected` | The whole file was checked and no watermark was found |
| `inconclusive` | A candidate was found, but not with enough confidence to decide |
| `unsupported` | The input cannot be processed. The credit is restored |
| `error` | Detection failed. This is not the same as "no watermark". The credit is restored |

- `result.watermarkText` is the embedded text. It is returned only when the result is `detected`, your account embedded the watermark, and exactly one embed record matches. Otherwise it is `null`.
- `result.reportSupported` tells you whether you can create a PDF report for this result. It is `false` when you checked an image captured from a PDF.
- If `processingDelayed` is `true`, automatic retries are exhausted and the order is waiting for manual recovery. It stays `inProgress`, so keep polling or wait for the webhook.

<Note>
  Webhook payloads keep the v2 field names: `order.watermarkExtract.completed` reports the outcome in `statusCode`, which uses `undetected` for `not_detected`, plus `watermarkFound` and `watermarkInfo.text`. See [Webhooks](/webhooks) for the full payload.
</Note>

## Step 4: Create a PDF report (optional)

When `result.reportSupported` is `true`, you can create a PDF report of the result in Korean (`ko-KR`), English (`en-US`), or Japanese (`ja-JP`). Reports for PDF files support `ko-KR` only. A report uses 1 credit, charged only when it is generated successfully.

Request the report, then poll it until `status` is `completed`:

<CodeGroup>
```bash cURL
curl -X POST https://api.bizmori.com/api/v3/orders/1234567891/reports \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{ "locale": "en-US" }'

curl https://api.bizmori.com/api/v3/orders/1234567891/reports/en-US \
  -H "Authorization: Bearer YOUR_API_KEY"
```

```javascript Node.js
async function createReport(orderId, locale) {
  const created = await fetch(`${API_BASE}/orders/${orderId}/reports`, {
    method: 'POST',
    headers: { ...headers, 'Content-Type': 'application/json' },
    body: JSON.stringify({ locale }),
  });
  if (!created.ok) throw new Error((await created.json()).code);

  for (let delay = 2000; ; delay = Math.min(delay * 1.5, 15000)) {
    const res = await fetch(`${API_BASE}/orders/${orderId}/reports/${locale}`, { headers });
    const { data: report } = await res.json();
    if (report.status === 'completed') return report.download.url;
    if (report.status === 'failed') throw new Error(report.failure.code);
    await sleep(delay);
  }
}

const reportUrl = await createReport(order.orderId, 'en-US');
```

## Full React example

Everything above, wired into one component: two file pickers, uploads with progress, backoff polling, the result rendered from `detectionStatus`, and a report button. No dependencies beyond React.

```jsx WatermarkExtractChecker.jsx
import { useRef, useState } from 'react';

const API_BASE = 'https://api.bizmori.com/api/v3';
const API_KEY = import.meta.env.VITE_MORI_API_KEY;

const CONTENT_TYPES = {
  jpg: 'image/jpeg', jpeg: 'image/jpeg', png: 'image/png', webp: 'image/webp',
  bmp: 'image/bmp', tif: 'image/tiff', tiff: 'image/tiff', pdf: 'application/pdf',
};
const ACCEPT_FORMATS = Object.keys(CONTENT_TYPES).map((ext) => `.${ext}`).join(',');
const REPORT_LOCALE = 'en-US';

const RESULT_LABELS = {
  detected: 'Watermark detected',
  not_detected: 'No watermark was found in this file.',
  inconclusive: 'A possible watermark was found, but the result is inconclusive.',
  unsupported: 'This file cannot be checked. The credit was restored.',
  error: 'Detection failed. The credit was restored — try again.',
};

const sleep = (ms) => new Promise((resolve) => setTimeout(resolve, ms));
const contentTypeOf = (name) => CONTENT_TYPES[name.split('.').pop().toLowerCase()];

async function api(path, { method = 'GET', body, idempotencyKey } = {}) {
  // Retries reuse the caller's idempotency key, so a retried create can never
  // produce a second order. Auth failures surface as `AUTH_*` codes — retrying
  // those will not help, so they fall through to the throw below.
  for (let attempt = 0; ; attempt++) {
    const res = await fetch(`${API_BASE}${path}`, {
      method,
      headers: {
        Authorization: `Bearer ${API_KEY}`,
        ...(body && { 'Content-Type': 'application/json' }),
      },
      body: body && JSON.stringify({ idempotencyKey, ...body }),
    });

    if (!res.ok) {
      const { code } = await res.json().catch(() => ({}));
      // 429 covers two cases: a transient rate limit, and PLAN_LIMIT_EXCEEDED,
      // which means the plan quota is spent and will never clear on retry.
      if (res.status === 429 && code !== 'PLAN_LIMIT_EXCEEDED' && attempt < 3) {
        await sleep(2 ** attempt * 1000);
        continue;
      }
      throw new Error(code ?? `HTTP_${res.status}`);
    }
    return (await res.json()).data;
  }
}

function putFile(file, uploadUrl, onProgress) {
  return new Promise((resolve, reject) => {
    const xhr = new XMLHttpRequest();
    xhr.open('PUT', uploadUrl);
    xhr.setRequestHeader('Content-Type', contentTypeOf(file.name));

    xhr.upload.onprogress = (event) => {
      if (event.lengthComputable) onProgress(event.loaded / event.total);
    };
    xhr.onload = () =>
      xhr.status < 300 ? resolve() : reject(new Error(`UPLOAD_FAILED_${xhr.status}`));
    xhr.onerror = () => reject(new Error('UPLOAD_NETWORK_ERROR'));

    xhr.send(file);
  });
}

async function poll(fetchOnce, isDone, { timeoutMs = 10 * 60 * 1000 } = {}) {
  const deadline = Date.now() + timeoutMs;
  let delay = 2000;

  while (Date.now() < deadline) {
    const value = await fetchOnce();
    if (isDone(value)) return value;

    await sleep(delay);
    delay = Math.min(delay * 1.5, 15000);
  }
  throw new Error('POLL_TIMEOUT');
}

export default function WatermarkExtractChecker() {
  const [originalFile, setOriginalFile] = useState(null);
  const [checkedFile, setCheckedFile] = useState(null);
  const [progress, setProgress] = useState(0);
  const [status, setStatus] = useState('idle');
  const [order, setOrder] = useState(null);
  const [error, setError] = useState(null);
  const inFlight = useRef(false);

  const busy = status !== 'idle' && status !== 'complete';
  const canSubmit =
    originalFile !== null &&
    checkedFile !== null &&
    contentTypeOf(originalFile.name) !== undefined &&
    contentTypeOf(checkedFile.name) !== undefined &&
    !busy;

  async function checkWatermark(event) {
    event.preventDefault();
    if (inFlight.current || !canSubmit) return;
    inFlight.current = true;

    // Snapshot the selection. The user can swap files while requests are in
    // flight, and each file has to stay paired with its upload URL.
    const original = originalFile;
    const checked = checkedFile;
    setError(null);
    setOrder(null);
    setProgress(0);

    try {
      setStatus('creating order');
      const created = await api('/orders/wtr-extract', {
        method: 'POST',
        idempotencyKey: crypto.randomUUID(),
        body: { file: { fileName: checked.name, originalFile: { fileName: original.name } } },
      });
      setOrder(created);

      setStatus('uploading');
      // files[0] is the original, files[1] is the file to check.
      await Promise.all([
        putFile(original, created.files[0].uploadUrl, () => {}),
        putFile(checked, created.files[1].uploadUrl, setProgress),
      ]);

      const finished = await poll(
        () => api(`/orders/${created.orderId}`),
        (current) => {
          setStatus(current.status);
          return ['complete', 'failed', 'expired'].includes(current.status);
        },
      );
      if (finished.status !== 'complete') throw new Error(`ORDER_${finished.status.toUpperCase()}`);

      setOrder(finished);
      setStatus('complete');
    } catch (caught) {
      setError(caught.message);
      setStatus('idle');
    } finally {
      inFlight.current = false;
    }
  }

  // The report URL expires after 300 seconds, so fetch it on every click.
  async function openReport() {
    try {
      await api(`/orders/${order.orderId}/reports`, { method: 'POST', body: { locale: REPORT_LOCALE } });
      const report = await poll(
        () => api(`/orders/${order.orderId}/reports/${REPORT_LOCALE}`),
        (current) => ['completed', 'failed'].includes(current.status),
      );
      if (report.status === 'failed') throw new Error(report.failure.code);
      window.location.assign(report.download.url);
    } catch (caught) {
      setError(caught.message);
    }
  }

  const result = status === 'complete' ? order?.result : null;

  return (
    <form onSubmit={checkWatermark}>
      <label>
        Original file
        <input
          type="file"
          accept={ACCEPT_FORMATS}
          disabled={busy}
          onChange={(event) => setOriginalFile(event.target.files[0] ?? null)}
        />
      </label>
      <label>
        File to check
        <input
          type="file"
          accept={ACCEPT_FORMATS}
          disabled={busy}
          onChange={(event) => setCheckedFile(event.target.files[0] ?? null)}
        />
      </label>
      <button type="submit" disabled={!canSubmit}>
        Check for watermark
      </button>

      {status !== 'idle' && <p>Status: {status}</p>}
      {status === 'uploading' && <p>Uploading: {Math.round(progress * 100)}%</p>}

      {/* `status` says the order finished; `result.detectionStatus` says what was found. */}
      {result && (
        <p>
          {RESULT_LABELS[result.detectionStatus]}
          {result.watermarkText && <strong> {result.watermarkText}</strong>}
        </p>
      )}
      {result?.reportSupported && (
        <button type="button" onClick={openReport}>
          Download PDF report
        </button>
      )}
      {error && <p role="alert">Failed: {error}{order && ` (orderId: ${order.orderId})`}</p>}
    </form>
  );
}
```

<Note>
  `import.meta.env.VITE_MORI_API_KEY` is Vite's syntax. Use `process.env.NEXT_PUBLIC_MORI_API_KEY` on Next.js, or whatever your bundler exposes to client code. `crypto.randomUUID()` needs a secure context: HTTPS and `localhost` are fine, a plain-HTTP LAN address is not.
</Note>

The public result contains only `detectionStatus`, `reportSupported`, and `watermarkText`. It never includes a watermark ID (MID).

## Error handling

| HTTP Status | Meaning | Action |
|-------------|---------|--------|
| `400` | Invalid request, `REPORT_LOCALE_UNSUPPORTED`, or `ORDER_EXPIRED` after the retention period | Check parameters, file extensions, and the report locale |
| `401` | Authentication failed | Verify your API key |
| `404` | `ORDER_NOT_FOUND`, or `REPORT_NOT_FOUND` for a locale you haven't requested | Check the order ID, and create the report before getting it |
| `409` | `WATERMARK_V2_CONFLICT` for a reused `idempotencyKey`, or `REPORT_NOT_AVAILABLE` when the result does not support a report | Use a new `idempotencyKey`, or check `result.reportSupported` |
| `429` | Rate limit, or `PLAN_LIMIT_EXCEEDED` when the plan quota is spent | Check the `code` field. A rate limit clears on retry; `PLAN_LIMIT_EXCEEDED` does not — upgrade the plan |
| `503` | Watermark processing or report generation is temporarily unavailable | Retry later |

For the complete error code reference, see [Error Codes](/errors).

## Migrating from v2 to v3

v3 always compares the file to check against its original, so the request now names both files.

| | v2 | v3 |
|---|---|---|
| Create an order | `POST /api/v2/orders/wtr-extract` | `POST /api/v3/orders/wtr-extract` |
| Original file | Optional (`includeOriginal`), images only | Required for every order, images and PDFs |
| Request body | `file.fileName`, `file.includeOriginal`, `file.originalFile` | `file.fileName` and `file.originalFile.fileName`. There is no `includeOriginal` |
| Uploads | One file, or two with `includeOriginal` | Always two: `files[0]` is the original, `files[1]` is the file to check |
| Get the result | `GET /api/v2/orders/{orderId}` → `statusCode` (`detected` / `undetected`) | [`GET /api/v3/orders/{orderId}`](/api-reference/orders/get-order-v3) → `result.detectionStatus` (five values), `result.watermarkText`, `result.reportSupported` |
| Credits | 1 credit per image; a PDF uses 1 credit per page | 1 credit per order, for images and PDFs alike. `unsupported` and `error` results are refunded |
| PDF report | Not available | [Create](/api-reference/reports/create-report) and [get](/api-reference/reports/get-report) a report |
| Confirm step | None | None |
| Webhooks | `order.watermarkExtract.completed` / `failed` | Same event names and `data` fields. `statusCode` can also be `inconclusive`, `unsupported`, or `error` |

<Warning>
  Use the v3 endpoints for orders you create with v3. `GET /api/v2/orders/{orderId}` returns only the common fields of a v3 order, without `result`, and `GET /api/v3/orders/{orderId}` returns `404 ORDER_NOT_FOUND` for a v2 order.
</Warning>
